# computed 缓存与失效

> **本章目标：**按需求值、版本检测与只读计算。建议预留约 23 分钟，先理解机制，再沿源码验证。

## 一、理解核心原理

computed 是惰性派生状态：没有读取需求时不必执行 getter，没有上游变化时可复用缓存。Vue 3.5 还使用依赖与版本信息减少不必要的重新计算。

这一步先明确**哪个对象持有状态、哪个动作导致状态变化、哪个函数接收变化**，再把同一套概念对照实际代码；直接背 API 很难解释异常行为。

## 二、源码追踪与调用链

固定源码文件：[`packages/reactivity/src/computed.ts`](source:packages/reactivity/src/computed.ts#computed)。建议先在右侧搜索 `computed`，必要时点击右上角链接在 GitHub 查看当前 tag 的完整上下文。

读取 total.value → 检查失效或版本 → 必要时运行 getter → 缓存结果；上游变化 → 通知下游 → 下一次访问刷新。

重点确认函数的参数、返回值、依赖的上下文，以及执行前后哪些数据结构被改变。遇到其他文件里的函数调用时，记录跨文件边界，不要只在单个函数里阅读。

## 三、最小可验证示例

```ts
import { ref, computed } from 'vue'
const price = ref(12), quantity = ref(2)
const total = computed(() => price.value * quantity.value)
console.log(total.value, total.value) // 第二次访问复用缓存
```

试着预测每一次读取、写入或渲染的输出顺序。与 [Mini Vue 的教学实现](mini:effect.mjs#effect) 对比时，注意它只复刻某些核心不变量，没有覆盖 Vue 3.5 的全部优化和边界行为。

## 四、容易理解错的地方

getter 应保持纯函数；不要在 computed 内进行网络请求、修改上游状态或依赖不受追踪的外部可变值。

阅读源码时，区分**公开 API 合约**、**当前 v3.5.43 实现细节**和**教学模型**；版本更新可能改变内部字段、调度细节与优化分支，不能把某个版本的内部结构当成永久保证。
