# track / trigger 与 Dep

> **本章目标**：读写时收集依赖，变化时通知订阅者。建议预留约 32 分钟，先理解机制，再沿源码验证。

## 一、理解核心原理

教学模型常用 WeakMap → Map → Set 来展示目标、键与订阅者。Vue 3.5 的实际实现进一步使用 Dep、Link 及版本信息维护关联，不应把简化模型视为源码逐行结构。

这一步先明确**哪个对象持有状态、哪个动作导致状态变化、哪个函数接收变化**，再把同一套概念对照实际代码；直接背 API 很难解释异常行为。

## 二、源码追踪与调用链

固定源码文件：[`packages/reactivity/src/dep.ts`](source:packages/reactivity/src/dep.ts#track)。建议先在右侧搜索 `track`，必要时点击右上角链接在 GitHub 查看当前 tag 的完整上下文。

代理读取 → track(target,type,key) → 定位 Dep → 把当前活动的订阅者连接到 Dep；修改数据 → trigger → 按类型找到相关依赖并通知。

重点确认函数的参数、返回值、依赖的上下文，以及执行前后哪些数据结构被改变。遇到其他文件里的函数调用时，记录跨文件边界，不要只在单个函数里阅读。

## 四、容易理解错的地方

数组 length、对象键迭代和 Map/Set 集合操作有特殊依赖触发规则；不是所有操作都只关心单个普通属性。

阅读源码时，区分**公开 API 合约**、**当前 v3.5.43 实现细节**和**教学模型**；版本更新可能改变内部字段、调度细节与优化分支，不能把某个版本的内部结构当成永久保证。
